# Tokenizer

## 相关概念

1. tokenization：将原始的文本信息（一般为Unicode字符串）映射到离散的 Tokens 列表的步骤。
2. token：LLM处理文本的基本单位，一个 Token 可以是一个完整的单词、一个词的一部分（如前缀或后缀）、一个标点符号，甚至是一个单个字符。
3. encode（编码）：将token转化为特定整数的过程，这个整数被称为code point，每一个code point都对应了一个独特的token。
4. decode（解码）：将整数数组重新转化成文本字符串的过程。

## 常见分词方法

### character-based tokenization

| 特征     | 描述                                                         |
| -------- | :----------------------------------------------------------- |
| 基本单位 | 单个 Unicode 字符（例如：'H', 'e', 'l', 'l', 'o', '🌍', '!'）。 |
| 编码方式 | 每个字符转换为其 Unicode 码点（整数）。例如 $ \text{ord}(a) = 97 $，$ \text{ord}(🌍) = 127757 $。 |
| 词汇表   | 非常大，因为大约有 150K 个 Unicode 字符。                    |
| 序列长度 | 很长，因为一个字符对应一个 Token，导致压缩率低。             |
| 存在问题 | 1. 词汇表太大。2. 许多字符（如 '🌍'）很罕见，导致对词汇表的使用效率低下。 |

### Byte-based tokenization

| 特征     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 基本单位 | 单个字节（一个 0 到 255 之间的整数）。                       |
| 编码方式 | Unicode 字符串首先被编码为字节序列，最常用的是 UTF-8。例如，`"a"` 是一个字节，而 `"🌍"` 是多个字节（`b'\xf0\x9f\x8c\x8d'`）。 |
| 词汇表   | 小且固定，只有 256 个。                                      |
| 序列长度 | 很长，因为压缩率为 1（即一个 Token 只有一个字节）。序列太长会导致 Transformer 的注意力机制（通常是二次复杂度）效率低下。 |
| 存在问题 | 压缩率非常差，序列太长。                                     |

词汇表的大小只有256,很明显是表示不完所有字符的。所以一个字符会被拆成多个 0-255 之间的整数，但是这又引出了一个新的问题：解码时会分不清哪几个整数该组成一个字符。为此需要设计一套变长的编码方案。

以UTF-8为例，通过字节的开头几个比特位，就能判断这个字节是一个字符的开始还是某个字符的后续部分：

| **字节数** | **字符范围 (十六进制)** | **字节 1 的二进制特征**    | **字节 2..n 的二进制特征** |
| ---------- | ----------------------- | -------------------------- | -------------------------- |
| **1 字节** | `0000-007F`             | `0xxxxxxx` (以 0 开头)     | 无                         |
| **2 字节** | `0080-07FF`             | `110xxxxx` (以 110 开头)   | `10xxxxxx` (以 10 开头)    |
| **3 字节** | `0800-FFFF`             | `1110xxxx` (以 1110 开头)  | `10xxxxxx` (以 10 开头)    |
| **4 字节** | `10000-10FFFF`          | `11110xxx` (以 11110 开头) | `10xxxxxx` (以 10 开头)    |

第一个字节的前几位决定了这个字符由几个字节组成，后面的所有字节都以10开头，表示这是该字符的后续部分。

e.g.对于汉字“你”：

它编码后的结果为`4F60`，即`0100 1111 0110 0000`

判断范围，是一个三字节的字符。套用模板`1110`,`10`,`10`

最终结果为`11100100 10111101 10100000`，也就是`b'\xe4\xbd\xa0'`

### word-based tokenization

| 特征     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 基本单位 | 完整的单词或通过正则表达式分割的语段。                       |
| 编码方式 | 将每个语段映射到一个整数 ID。                                |
| 词汇表   | 巨大，每一个单词/语段都需要被设置成一个单独的词汇。          |
| 存在问题 | 1. 词汇量巨大。2. 许多单词很罕见。3. 新词汇（训练时未见过的词）会得到一个特殊的 UNK (Unknown) Token，这会影响计算。 |

### BPE（Byte-Pair Encoding）

1994年被提出，在 2016 年被 Sennrich 等人引入自然语言处理（NLP）领域，用于神经机器翻译，并被 GPT-2 等现代 LLM 广泛采用。之前传统NLP所采用的分词方法基本都是word-based tokenization。

核心思想：通过在原始文本上训练 Tokenizer 来自动确定词汇表。它是一种有效的启发式方法，利用语料库统计数据来确定 Token。常用的字符序列用一个 Token 表示，罕见的序列用多个 Token 表示。

训练过程：从字符串的字节列表开始，重复合并出现频率最高的相邻 Token 对，每合并一次，就会产生一个新的 Token 索引，词汇表也随之扩大。

| 特征     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 基本单位 | 子词（subword）Token；从“字符/字节”起步，通过合并得到更长的常见片段（例如把 `t`+`h` 合并成 `th`）。 |
| 编码方式 | 训练阶段统计语料中相邻 Token 对的频次，反复合并最高频的一对并加入词表；推理阶段按学习到的合并规则把输入逐步合并，最终映射为 Token ID 序列。 |
| 词汇表   | 可控且固定：初始词表（字符或字节） + 若干次合并产生的新 Token；大小通常由“合并次数/目标 vocab size”决定。 |
| 序列长度 | 介于 byte/char 与 word 之间：常见片段会被合并成更长 Token，压缩率更好，序列更短；罕见词仍会被拆成多个子词。 |
| 优点     | 1. 基本避免 UNK：新词可以拆成已知子词。2. 词表大小与序列长度可折中调节。3. 对多语言/噪声文本相对鲁棒（尤其是 byte-level BPE）。 |
| 存在问题 | 1. 合并是基于频次的启发式，得到的子词边界不一定符合语言学直觉。2. 不同语料训练出的合并规则差异大，可能影响跨域泛化。 |

## BPE实现

### initialization

- **输入**：实例化参数（如 `pattern` 等）。
- **输出**：基础状态初始化的 Tokenizer 实例。
- **该实现逻辑**：完成 BPE 训练时及实例化 Tokenizer 时的基础状态初始化。在 Tokenizer 实例化时（`__init__`），直接初始化固定的 256 大小的基础字节词表 (`vocab`) 和字节编码映射 (`byte_encoder`)。可合并次数 `num_merges` 会在具体的训练pipeline中根据目标词表大小动态计算。

### pre-tokenization

把原始文本切分为 chunk，并完成“去重 + 计数”，转换成更为紧凑的字典结构，为后续高性能 pair 统计提速。优先处理特殊 Token，避免它们被错误合并或切分。用字典维护 Token 频率既能保证全局去重，又方便我们在后面的合并循环中快速更新特定片段的词频。这一步结束后，我们就得到了“唯一字节序列 + 频次”这组紧凑表示，可直接用于下一步的 pair 频次统计与合并决策。

- **输入**：
  1. `text`：原始字符串。
  2. `special_tokens`：特殊 token 列表，在正则切分前使用这些特殊 token 先进行分割。
- **输出**：一个字典 `pretoken_counts`，键是每个唯一的词片段（用 UTF-8 字节 ID 的 tuple 表示），值是其在文本中出现的频次。

```python
def pre_tokenization(self, text: str, special_tokens: list[str] | None = None) -> dict[tuple[int, ...], int]:
        pretoken_counts: dict[tuple[int, ...], int] = {}
        pieces = [text]

        if special_tokens:
            split_pattern = "|".join(
                re.escape(token) for token in sorted(set(special_tokens), key=len, reverse=True)
            )
            pieces = re.split(split_pattern, text)

        for piece in pieces:
            if not piece:
                continue
            for match in self.compiled_pattern.finditer(piece):
                token_ids = tuple(match.group(0).encode("utf-8"))
                pretoken_counts[token_ids] = pretoken_counts.get(token_ids, 0) + 1

        return pretoken_counts
```

### compute and merge

在给定合并预算内，高效地完成“统计 pair 频次 -> 选择最优 pair -> 执行合并”，学习 merge 规则，并记录合并的优先级（Rank）以供编码时使用。相比于每轮都重新扫描所有片段来统计配对，实现中维护了 `pair_counts`（每个配对出现的总频率）和 `pair_to_words`（某个配对出现在哪些具体的片段中）的数据结构：

- 每选出一个本轮最优 `best_pair`（频次并列时利用左字节串和右字节串组合的大小作为次级比较 tie-break），分配新 ID。

- 只针对包含这个 `best_pair` 的相关片段（`affected_words`）进行局部更新。旧片段从 `pair_to_words` 中移除，生成新片段后再将涉及的配对重新加入统计。

- 同步记录 `self.merge_ranks[best_pair] = rank`，此处 Rank 越小代表越早被合并，优先级越高。

- **输入**：
  1. `pretoken_counts`：由预分词产生的各个 chunk 片段的频次表。
  2. `num_merges`：最多执行多少轮合并。
- **输出**：
  1. `merges_in_order`：记录每一轮被合并的按顺序排列的字节对（bytes pair）。
  2. 更新类的内部状态：包括词表 `vocab`，合并规则 `merges`，以及极为重要的合并优先级 `merge_ranks`。

```python
def compute_merge(
        self,
        pretoken_counts: dict[tuple[int, ...], int],
        num_merges: int,
    ) -> list[tuple[bytes, bytes]]:
        merges_in_order: list[tuple[bytes, bytes]] = []
        next_id = 256
        word_counts = dict(pretoken_counts)
        pair_counts: dict[tuple[int, int], int] = {}
        pair_to_words: dict[tuple[int, int], set[tuple[int, ...]]] = {}

        for word, freq in word_counts.items():
            if len(word) < 2:
                continue
            for pair in zip(word, word[1:]):
                pair_counts[pair] = pair_counts.get(pair, 0) + freq
                if pair not in pair_to_words:
                    pair_to_words[pair] = {word}
                else:
                    pair_to_words[pair].add(word)

        for rank in range(num_merges):
            if not pair_counts:
                break

            best_pair = max(
                pair_counts,
                key=lambda pair: (pair_counts[pair], self.vocab[pair[0]], self.vocab[pair[1]]),
            )
            merged_id = next_id
            next_id += 1

            left_bytes = self.vocab[best_pair[0]]
            right_bytes = self.vocab[best_pair[1]]
            merged_bytes = left_bytes + right_bytes

            self.vocab[merged_id] = merged_bytes
            self.merges[best_pair] = merged_id
            self.merge_ranks[best_pair] = rank
            merges_in_order.append((left_bytes, right_bytes))

            affected_words = list(pair_to_words.get(best_pair, ()))
            merged_word_counts: dict[tuple[int, ...], int] = {}

            for word in affected_words:
                freq = word_counts.pop(word, 0)
                if freq == 0:
                    continue

                word_pairs = list(zip(word, word[1:]))
                for pair in word_pairs:
                    updated_count = pair_counts[pair] - freq
                    if updated_count == 0:
                        del pair_counts[pair]
                    else:
                        pair_counts[pair] = updated_count

                for pair in set(word_pairs):
                    words_with_pair = pair_to_words[pair]
                    words_with_pair.discard(word)
                    if not words_with_pair:
                        del pair_to_words[pair]

                merged_word = merge_pair(word, best_pair, merged_id)
                merged_word_counts[merged_word] = merged_word_counts.get(merged_word, 0) + freq

            for word, freq in merged_word_counts.items():
                word_counts[word] = word_counts.get(word, 0) + freq
                if len(word) < 2:
                    continue
                for pair in zip(word, word[1:]):
                    pair_counts[pair] = pair_counts.get(pair, 0) + freq
                    if pair not in pair_to_words:
                        pair_to_words[pair] = {word}
                    else:
                        pair_to_words[pair].add(word)

        return merges_in_order
```

### special tokens

由于特殊 token 不参与 BPE 的 pair 合并学习，需要将特殊 token 作为单独的字面量直接注册并放入词表中。

- **输入**：`special_tokens`（特殊 token 列表或字典，例如 `<|endoftext|>`、换行占位符等）。
- **输出**：更新内部状态 `special_tokens` 和 `inverse_special_tokens`，并利用它们扩展词表。

```python
def register_special_tokens(self, special_tokens: list[str] | dict[str, int] | None) -> None:
        if special_tokens is None:
            mapping: dict[str, int] = {}
        elif isinstance(special_tokens, dict):
            mapping = dict(special_tokens)
        elif isinstance(special_tokens, list):
            mapping = {}
            next_id = max(self.vocab, default=-1) + 1
            bytes_to_id = {token_bytes: token_id for token_id, token_bytes in self.vocab.items()}
            for token in special_tokens:
                token_bytes = token.encode("utf-8")
                token_id = bytes_to_id.get(token_bytes)
                if token_id is None:
                    token_id = next_id
                    next_id += 1
                    self.vocab[token_id] = token_bytes
                    bytes_to_id[token_bytes] = token_id
                mapping[token] = token_id
        else:
            raise TypeError("special_tokens must be None, list[str], or dict[str, int]")

        self.special_tokens = mapping
        self.inverse_special_tokens = {token_id: token for token, token_id in mapping.items()}

        for token, token_id in mapping.items():
            self.vocab[token_id] = token.encode("utf-8")
```

### train

经过上述步骤后我们已经实现了一个基本的BPE，下面就可以正式开始训练了。该步骤负责串联切分原始文本、计算合并轮次以及高频配对合并的流程。它根据预期的目标词表大小计算出需要合并的次数 `num_merges`，随后依次调用预切分（`pre_tokenization`）、计算合并（`compute_merge`）和注册特殊 token（`register_special_tokens`）。

- **输入**：
  1. `input_path`：用于训练的语料文件路径。
  2. `vocab_size`：期望得到的目标词表大小。
  3. `special_tokens`：需要注册的特殊 token 列表。
  4. `pattern`：预分词正则表达式。
- **输出**：训练后得到的完整词表 `vocab` 和合并规则 `merges`。

```python
@classmethod
def train_bpe(
        cls,
        input_path: str | Path,
        vocab_size: int,
        special_tokens: list[str],
        pattern: str = GPT2_SPLIT_PATTERN,
    ) -> tuple[dict[int, bytes], list[tuple[bytes, bytes]]]:
        tokenizer = cls(pattern=pattern)
        with open(input_path, encoding="utf-8") as f:
            text = f.read()

        tokenizer.vocab = {i: bytes([i]) for i in range(256)}
        tokenizer.byte_encoder = {i: i for i in range(256)}
        tokenizer.merges = {}
        tokenizer.merge_ranks = {}
        tokenizer.special_tokens = {}
        tokenizer.inverse_special_tokens = {}

        num_merges = max(0, vocab_size - 256 - len(special_tokens or []))
        pretoken_counts = tokenizer.pre_tokenization(text, special_tokens)
        merges = tokenizer.compute_merge(pretoken_counts, num_merges)
        tokenizer.register_special_tokens(special_tokens)

        return dict(tokenizer.vocab), merges
```

如上所示，得到了词表（`vocab`）以及合并规则（`merges`）后，Tokenizer 就可以投入实际部署及推理使用。下面分别说明编码和解码流程。

### 编码

编码过程负责将输入文本转化为对应的 Token ID 列表。它正确处理特殊 Token，并将普通文本按照训练得到的合并规则进行迭代合并。编码流程分为三个递进的处理层次：

1. 特殊 Token 切分 (`encode`)：根据 `allowed_special` 处理特殊 Token，通过分割将文本切成小段。
2. 正则分片 (`encode_ordinary`)：使用训练时相同的正则表达式（如 `GPT2_SPLIT_PATTERN`）将常规文本切分为极小的 chunk，依次送入 `encode_pretoken` 防止跨词级别的越界合并。
3. 优先级字节合并 (`encode_pretoken`)：这里利用了我们在 `compute_merge` 中记录的合并轮次 `merge_ranks`（相当于配对的优先级表）。每次迭代只需要找到 rank 值最靠前（即最早发生，优先级最高）的相邻子节配对进行合并，极大降低了编码的时间复杂度。

- **输入**：
  1. `text`：需要编码的原始字符串。
  2. `allowed_special`：允许的特殊 Token 集合，控制如何处理文本中出现的特殊 Token。
- **输出**：短整列表 `ids`：编码后的 Token ID 列表。

```python
def encode_pretoken(self, token_bytes: bytes) -> list[int]:
        ids = [self.byte_encoder[byte] for byte in token_bytes]

        while len(ids) >= 2:
            best_pair: tuple[int, int] | None = None
            best_rank: int | None = None

            for pair in zip(ids, ids[1:]):
                rank = self.merge_ranks.get(pair)
                if rank is None:
                    continue
                if best_rank is None or rank < best_rank:
                    best_pair = pair
                    best_rank = rank

            if best_pair is None:
                break

            ids = list(merge_pair(ids, best_pair, self.merges[best_pair]))

        return ids

def encode_ordinary(self, text: str) -> list[int]:
        ids: list[int] = []
        for match in self.compiled_pattern.finditer(text):
            ids.extend(self.encode_pretoken(match.group(0).encode("utf-8")))
        return ids

def encode(self, text: str, allowed_special: str | set[str] = "all") -> list[int]:
        if allowed_special == "all":
            special = self.special_tokens
        elif allowed_special == "none":
            special = {}
        elif allowed_special == "none_raise":
            if any(token in text for token in self.special_tokens):
                raise ValueError("text contains a disallowed special token")
            special = {}
        elif isinstance(allowed_special, set):
            special = {token: token_id for token, token_id in self.special_tokens.items() if token in allowed_special}
        else:
            raise ValueError(f"unsupported allowed_special={allowed_special}")

        if not special:
            return self.encode_ordinary(text)

        split_pattern = "(" + "|".join(re.escape(token) for token in sorted(special, key=len, reverse=True)) + ")"
        parts = re.split(split_pattern, text)

        ids: list[int] = []
        for part in parts:
            if not part:
                continue
            token_id = special.get(part)
            if token_id is not None:
                ids.append(token_id)
            else:
                ids.extend(self.encode_ordinary(part))
        return ids
```

### 解码

将 Token ID 列表还原回人类可读的连续字符串。解码时只需遍历 Token ID 列表，在已有词表 `vocab` 中查找对应的字节片段进行拼接，最后统一调用 `decode("utf-8", errors="replace")`，有效防止非完整字截断导致的解码报错。

- **输入**：`ids`（Token ID 列表）。
- **输出**：`text`（解码还原的完整字符串）。

```python
def decode(self, ids: list[int]) -> str:
        chunks: list[bytes] = []
        for token_id in ids:
            token_bytes = self.vocab.get(token_id)
            if token_bytes is None:
                raise ValueError(f"invalid token id: {token_id}")
            chunks.append(token_bytes)
        return b"".join(chunks).decode("utf-8", errors="replace")
```

### 归一化与激活函数 (RMSNorm & SwiGLU)

大语言模型通常使用 `RMSNorm` 来代替传统的 `LayerNorm`，它去除了均值计算，只按均方根进行缩放，计算开销更小且效果相当。在自注意力模块之间，我们使用前馈神经网络进行特征非线性映射，当前大模型往往采用 `SwiGLU` 激活函数替代传统的 ReLU 或 GELU，它通过引入带有 `SiLU` (即 `x * sigmoid(x)`) 的门控机制，提升了模型的表达能力。

- **输入**：`x`，模型隐藏层的状态张量。
  - *示例*：输入形状为 `(batch_size, seq_len, d_model)` = `(2, 10, 256)`。
- **输出**：归一化或激活后的状态张量。
  - *示例*：输出形状保持不变，仍为 `(batch_size, seq_len, d_model)` = `(2, 10, 256)`。

```python
class RMSNorm(nn.Module):
    # 初始化参数定义部分 (eps, weight 等)...
    
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        in_dtype = x.dtype
        x = x.to(torch.float32)
        rms = torch.sqrt(torch.mean(x * x, dim=-1, keepdim=True) + self.eps)
        rmsnorm = (x / rms) * self.weight
        return rmsnorm.to(in_dtype)

class SwiGLU(nn.Module):
    # ...包含 w1, w2, w3 三个线性投影层
    
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        a = silu(self.w1.forward(x))
        b = self.w3.forward(x)
        return self.w2.forward(a * b)
```

### 旋转位置编码 (RoPE)

Transformer 本身天然缺少对序列顺序的感知。区别于早期的绝对位置编码，现代大模型普遍采用旋转位置编码（Rotary Position Embedding, RoPE）。它利用复数几何性质，将绝对位置信息以“旋转角度”的形式注入到 Query 和 Key 中，使得模型在计算点积注意力时能自然捕获相对位置衰减关系。

- **输入**：
  1. `x`：切分多头后的 Query 或 Key 向量。
     - *示例*：形状为 `(batch_size, num_heads, seq_len, d_head)` = `(2, 8, 10, 32)`。
  2. `token_positions`：Token 在上下文序列中的绝对位置序列索引。
     - *示例*：形状为 `(batch_size, seq_len)` = `(2, 10)`。
- **输出**：施加了旋转变换后的表征向量。
  - *示例*：输出形状保持与输入相同，即 `(2, 8, 10, 32)`。

```python
class RoPE:
    # 频率超参设定的初始化...
    
    def forward(self, x: torch.Tensor, token_positions: torch.Tensor) -> torch.Tensor:
        in_dtype = x.dtype
        x_fp32 = x.to(torch.float32)

        half = self.d_k // 2
        i = torch.arange(half, device=x.device, dtype=torch.float32)
        inv_freq = self.theta ** (-2.0 * i / self.d_k)
        
        # 显式把 token_positions 对齐广播至 x 的形状级别
        pos_shape = token_positions.shape[:-1] + (1,) * (x.ndim - 2 - (token_positions.ndim - 1)) + (token_positions.shape[-1], 1)
        pos = token_positions.to(device=x.device, dtype=torch.float32).reshape(pos_shape)

        angles = pos * inv_freq
        cos = torch.cos(angles)
        sin = torch.sin(angles)

        # 沿着最后一维将特征两两成对进行二位平面旋转
        x_pair = x_fp32.reshape(*x_fp32.shape[:-1], half, 2)
        x0, x1 = x_pair[..., 0], x_pair[..., 1]

        y0 = x0 * cos - x1 * sin
        y1 = x0 * sin + x1 * cos

        out = torch.stack((y0, y1), dim=-1).reshape_as(x_fp32)
        return out.to(in_dtype)
```

### 多头自注意力机制

这部分是大语言模型最为核心的信息交互机制。每一层的输入向量会首先经过线性投影产生 Query、Key、Value，同时切分为并发的多个 Attention Head 以捕捉不同子空间的关联特征。在此阶段：仅向 Query 和 Key 注入前述的 RoPE 位置感知；随后为了符合单向语言模型的自回归特性（即只能看前面字），生成一个严格的下三角因果掩码（Causal Mask）遮蔽未来的 Token；最后执行稳定的缩放点积注意力分数的计算加权合并，再由最后的线性层把众多的头表征投影拼合。

- **输入**：
  1. `x`：经过 Pre-Norm 处理后的特征。
     - *示例*：形状是 `(batch_size, seq_len, d_model)` = `(2, 10, 256)`。
  2. `token_positions`：透传的位置信息序列。
     - *示例*：形状是 `(batch_size, seq_len)` = `(2, 10)`。
- **输出**：完成上下文聚合与重新变换的特征向量。
  - *示例*：重新回归 `(batch_size, seq_len, d_model)` = `(2, 10, 256)` 的形状。

```python
class MultiHeadSelfAttention(nn.Module):
    # 维度定义、三组权重矩阵与 RoPE 注册...

    def forward(self, x: torch.Tensor, token_positions: Optional[torch.Tensor] = None) -> torch.Tensor:
        # 分布给各个独立的子头空间 x: (b, s, d_model) -> (b, h, s, d_head)
        q = self._split_heads(self.q_proj.forward(x))
        k = self._split_heads(self.k_proj.forward(x))
        v = self._split_heads(self.v_proj.forward(x))

        if self.use_rope:
            # v 不参与绝对位置相对演化
            q = self.rope.forward(q, token_positions)
            k = self.rope.forward(k, token_positions)

        # s 为当前上下文步长，借由 torch.tril 屏蔽上三角未来的连接节点
        s = x.shape[1]
        causal = torch.tril(torch.ones((s, s), dtype=torch.bool, device=x.device)).view(1, 1, s, s)

        # Attention核心：q矩阵和k矩阵相乘寻找关系度
        attn_out = scaled_dot_product_attention(q, k, v, mask=causal)
        out = self._merge_heads(attn_out)
        return self.output_proj.forward(out)
```

### Transformer块

如拼积木一般，单层 Transformer Block 由一个 MHSA多头注意力簇 与一个局部前置的 SwiGLU组成。业界基本均使用 **Pre-Norm** 架构架构重设计网络——即进入 Attention 及 FFN 分支之前优先进行 `RMSNorm` 规整（极大促进了庞大深度网络中的训练稳定性），各子网络也都会在外部额外包含直连残差连接保障深层梯度回授。

- **输入**：
  1. `x`：由上一层传递来蕴含早期信息的隐藏状态。
     - *示例*：形状 `(batch_size, seq_len, d_model)` = `(2, 10, 256)`。
  2. `token_positions`：Token的绝对位置索引，沿路透传至注意力。
     - *示例*：形状 `(batch_size, seq_len)` = `(2, 10)`。
- **输出**：本批次经注意力与感知提炼并且完成了残差相辅的高阶语义态。
  - *示例*：形状仍为 `(batch_size, seq_len, d_model)` = `(2, 10, 256)` 原状输出。

```python
class TransformerBlock(nn.Module):
    # 模块初始化：分别包含 ln1, attn, ln2 及 ffn 门...

    def forward(self, x: torch.Tensor, token_positions: torch.Tensor) -> torch.Tensor:
        # Pre-Norm 结构结合跳跃连积（Residual Sum）
        x = x + self.attn(self.ln1(x), token_positions)
        x = x + self.ffn(self.ln2(x))
        return x
```

### 语言模型整合主干

来到架构组装的终末阶段，我们可以彻底将这些拼图组装成能够接受分词产物、推测文本进程的完整因果模型——`TransformerLM`。它的主要执行路途：首先应用底层 `Embedding` 把原始断续 Token ID （即分词后的整数标识）映射填充成包含初始密度的词向量组；生成好步长定位锚点供给整个链条；然后循环穿透堆成的几十层 `TransformerBlock` 以抽取深级复杂语境；所有的处理完成后做一波 `Final Norm` 收尾规范；末端再利用一层巨大的线性头 `lm_head` 发射回预设词表的分布领域以得到预测几率总览。

- **输入**：`input_ids`，也就是本期传给模型的编码后 Token ID 阵列。
  - *示例*：假设一次读入2段文本且长度为10，那么它的输入形状就是 `(batch_size, seq_len)` = `(2, 10)` 整数标号矩阵。
- **输出**：`logits`，大模型给出的、对应整套字典里各个子词接着上一字符后面可能现身的能量推断。
  - *示例*：设本系列的分册字典共有32000个唯一词 `vocab_size=32000`，输出维就会散开成 `(batch_size, seq_len, vocab_size)` = `(2, 10, 32000)` 的三视浮点面。

```python
class TransformerLM(nn.Module):
    # 构建嵌入头、循环层阵列与顶层线性输出预测结构...

    def forward(self, input_ids: torch.Tensor) -> torch.Tensor:
        b, s = input_ids.shape
        if s > self.context_length:
            raise ValueError("sequence length exceeds context_length.")

        # 查询每个Token对应的连续词向量 (b, s) -> (b, s, d_model)
        x = self.token_embeddings.forward(input_ids) 

        # 构建各序列上绝对偏移步频并给到该次批度 (b, s)
        positions = torch.arange(s, device=input_ids.device).unsqueeze(0).expand(b, s)

        # 挨个贯穿所有的 Block 并不断更新特征
        for block in self.layers:
            x = block.forward(x, token_positions=positions)

        # 终态规范和预测空间放大 (b, s, d_model) -> (b, s, vocab_size)
        x = self.ln_final.forward(x)
        logits = self.lm_head.forward(x)  
        return logits
```

### 交叉熵损失 (Cross-Entropy Loss)

在训练语言模型时，我们通过计算模型输出的概率分布与真实的下一个 Token 之间的交叉熵差异，来指导模型不断优化。在这里我们自己实现了一个基础版本的交叉熵算子。为了保证数值计算的稳定，防止指数溢出等问题，通常先在 Log 空间通过 `logsumexp` 聚合归一化分布，接着扣除正确目标位的 logit 能量即为最终的 Loss（形式等价于直接计算 Softmax 的负对数似然）。

- **输入**：
  1. `inputs`：模型未归一化输出（Logits）。
     - *示例*：在将序列维度拉平后，形状为 `(batch_size * seq_len, vocab_size)` = `(20, 32000)`。
  2. `targets`：对应位上的实际真实 Token ID，作为正确参考类别（Ground Truth）。
     - *示例*：拉平后的形状就是一维的 `(batch_size * seq_len,)` = `(20,)`。
- **输出**：`loss`：均值合并后的标量常数，指示模型在此批次上的错误代价。
  - *示例*：标量（如 Tensor `2.341`），也就是一个形状为 `()` 的张量。

```python
def cross_entropy(inputs: torch.Tensor, targets: torch.Tensor) -> torch.Tensor:
    if inputs.ndim != 2:
        raise ValueError("inputs must have shape (batch_size, vocab_size)")
    if targets.ndim != 1:
        raise ValueError("targets must have shape (batch_size,)")
    if inputs.shape[0] != targets.shape[0]:
        raise ValueError("inputs and targets must have the same batch size")

    # 对数均值稳定算子： log(\sum exp(x))
    logsumexp = torch.logsumexp(inputs, dim=-1)
    
    # 提取正确位置分布的 logit 原值预测信息
    target_logits = inputs.gather(dim=-1, index=targets.unsqueeze(-1)).squeeze(-1)
    
    # 输出均值误差 (等效于原公式中 -log(exp(x_t) / sum(exp(x_i))) )
    return (logsumexp - target_logits).mean()
```

### SGD 与 AdamW 优化器

深度学习依靠优化策略通过梯度下降（Gradient Descent）来更新模型。最朴素的是梯度下降算法（**SGD**），它直接以一定学习率为步长向负梯度进发 $w_{new} = w_{old} - lr * ∇w$。
然而，SGD在处理起伏大或者方向稀疏的空间时效率相对较低。大语言模型领域目前更为标准的作法是采用 **AdamW**（带有权重衰减修正的Adam优化器）。它利用梯度的前几轮指数移动平均值（一次动量与二次动量）分别控制参数下降的方向与缩放自适应步长，能保证大参数域量级收敛。

- **输入**：`params` 及关联的超参数（如 `lr`, `betas`, `eps`, `weight_decay` 等），也就是我们构造好的语言模型 `TransformerLM` 所有需要被学习的权重。
  - *示例*：如一个包含了上百个参数群块、且累计参数量达到百万乃至千亿级的迭代器载体。
- **输出**：（类实例无直接Tensor输出）在调用 `.step()` 时会利用保存的二阶动量统计，直接就地修改网络权重（In-place update），同时可有条件的接受一个 `closure` 反馈实时 loss。

```python
class AdamW(torch.optim.Optimizer):
    def __init__(
        self,
        params,
        lr: float = 1e-3,
        betas: tuple[float, float] = (0.9, 0.999),
        eps: float = 1e-8,
        weight_decay: float = 0.01,
    ):
        defaults = {
            "lr": lr,
            "betas": betas,
            "eps": eps,
            "weight_decay": weight_decay,
        }
        super().__init__(params, defaults)

    @torch.no_grad()
    def step(self, closure=None):
        loss: Optional[torch.Tensor] = None
        if closure is not None:
            with torch.enable_grad():
                loss = closure()

        for group in self.param_groups:
            lr = group["lr"]
            beta1, beta2 = group["betas"]
            eps = group["eps"]
            weight_decay = group["weight_decay"]

            for p in group["params"]:
                if p.grad is None:
                    continue

                grad = p.grad
                if grad.is_sparse:
                    raise RuntimeError("AdamW does not support sparse gradients")

                state = self.state[p]
                # 参数动量状态历史初始置零
                if len(state) == 0:
                    state["step"] = 0
                    state["exp_avg"] = torch.zeros_like(p)
                    state["exp_avg_sq"] = torch.zeros_like(p)

                exp_avg = state["exp_avg"]
                exp_avg_sq = state["exp_avg_sq"]

                state["step"] += 1
                step_t = state["step"]

                # 分别累计动量均值与均方
                exp_avg.mul_(beta1).add_(grad, alpha=1.0 - beta1)
                exp_avg_sq.mul_(beta2).addcmul_(grad, grad, value=1.0 - beta2)

                # 修正初期偏置误差
                bias_correction1 = 1.0 - (beta1**step_t)
                bias_correction2 = 1.0 - (beta2**step_t)
                step_size = lr / bias_correction1
                denom = (exp_avg_sq.sqrt() / math.sqrt(bias_correction2)).add_(eps)

                # 独立执行权重衰减策略
                if weight_decay != 0.0:
                    p.mul_(1.0 - lr * weight_decay)

                # 修改原权重参数
                p.addcdiv_(exp_avg, denom, value=-step_size)

        return loss
```

### 学习率调度与梯度裁剪

在实际的 LLM 训练中，单纯有一个优化器还不够，我们需要控制 **学习率步伐轨迹** 并防止 **梯度大爆炸**，因此通常会加持以下两种辅助手段。

1. **梯度裁剪 (Gradient Clipping)**：通过截断单个反向传播批次的更新向量的总2范数长度（L2 Norm），强制保证权重的偏移步不会太极端。
2. **余弦退火学习率 (Cosine Learning Rate Schedule)**：大模型的学习率一般呈现为起步缓慢爬升（Warmup），随后依据余弦函数形态随迭代次数（Iteration）平滑下降至一个极小值，这是实现平稳深层收敛的最佳实践。

- **输入**（学习率计划示例）：
  - 当前步数 `it=20`，最大学习率 `max_learning_rate=1e-3`。
- **输出**：当前步应采用的学习率。
  - *示例*：在 Warmup （比如共100步）阶段内，输出可能按比率线性增长，返回如 `2.0e-4`。

```python
def gradient_clipping(parameters: Iterable[torch.nn.Parameter], max_l2_norm: float) -> None:
    torch.nn.utils.clip_grad_norm_(parameters, max_l2_norm)

def get_lr_cosine_schedule(
    it: int,
    max_learning_rate: float,
    min_learning_rate: float,
    warmup_iters: int,
    cosine_cycle_iters: int,
) -> float:
    # Warmup线性预热阶段
    if it < warmup_iters:
        if warmup_iters == 0:
            return max_learning_rate
        return max_learning_rate * (it / warmup_iters)

    if it <= warmup_iters:
        return max_learning_rate

    # 清零极值阶段
    if it >= cosine_cycle_iters:
        return min_learning_rate

    # 余弦滑降比率（Cosine Decay）
    decay_iters = cosine_cycle_iters - warmup_iters
    if decay_iters <= 0:
        return min_learning_rate

    decay_ratio = (it - warmup_iters) / decay_iters
    cosine_coeff = 0.5 * (1.0 + math.cos(math.pi * decay_ratio))
    return min_learning_rate + cosine_coeff * (max_learning_rate - min_learning_rate)
```

### 训练与验证循环

到这一步，我们就有了模型结构 (`TransformerLM`)、分词器提供的数据集、损失函数 (`cross_entropy`)、优化器 (`AdamW`) 以及学习率策略。最后我们只需要运用一个**训练循环 (Training Loop)** 将所有部分整合起来，驱动模型开始吸纳数据进行迭代学习。

在训练循环中，我们重复执行以下步骤：抽取数据批次、清理上一轮梯度、前向传播获取预测分布、核对真实标签计算损失、反向传播产生梯度、(可选)实施梯度裁剪、根据调度器更新学习率，最后驱动优化器步进修改模型参数。在大致经过一定步数后，我们还会穿插执行**验证循环 (Evaluation Loop)**，让模型在未见过的数据集上评估泛化能力并输出指标（如 Perplexity 与平均 Loss），以随时观察验证模型的训练健康度。

- **输入**：
  1. `model` 与 `optimizer`：待训练的初始化模型和与之绑定的优化引擎。
  2. `train_dataset`，`val_dataset`：训练与验证用的 token ID 一维数组。
     - *示例*：Numpy 格式的巨量整数数组 `[2, 341, 1025, ...]`，大小可达数千万甚至上百亿级别。
  3. 各类控制超参数，如 `batch_size`, `context_length`, `max_steps` 等。
- **输出**：训练全周期的状态汇报数据字典，包括统计总词数、平均速度以及最终的损失数值。
  - *示例*：`{"final_train_loss": 3.75, "steps": 1000, "tokens": 4096000, "tokens_per_s": 2e4}`。

```python
def evaluate_loop(
    model: torch.nn.Module,
    dataset: np.ndarray,
    batch_size: int,
    context_length: int,
    device: str,
    eval_steps: int,
) -> dict[str, float]:
    model_was_training = model.training
    model.eval()

    total_loss = 0.0
    total_tokens = 0

    with torch.no_grad():
        for _ in range(eval_steps):
            x, y = get_batch(dataset, batch_size=batch_size, context_length=context_length, device=device)
            logits = model(x)
            loss = cross_entropy(logits.reshape(-1, logits.size(-1)), y.reshape(-1))
            total_loss += float(loss.item())
            total_tokens += int(y.numel())

    if model_was_training:
        model.train()

    mean_loss = total_loss / max(1, eval_steps)
    perplexity = float(torch.exp(torch.tensor(mean_loss)).item())
    return {
        "loss": mean_loss,
        "perplexity": perplexity,
        "tokens": float(total_tokens),
    }


def train_loop(
    model: torch.nn.Module,
    optimizer: torch.optim.Optimizer,
    train_dataset: np.ndarray,
    val_dataset: np.ndarray | None,
    batch_size: int,
    context_length: int,
    max_steps: int,
    device: str,
    logger: TrainLogger | None = None,
    lr_schedule_fn: Callable[[int], float] | None = None,
    grad_clip_norm: float | None = None,
    eval_interval: int = 0,
    eval_steps: int = 10,
) -> dict[str, float | int]:
    if max_steps <= 0:
        raise ValueError("max_steps must be positive")

    model.to(device)
    model.train()

    start_time = time.time()
    total_tokens = 0
    final_loss = 0.0

    for step in range(max_steps):
        # 1. 动态学习率应用
        if lr_schedule_fn is not None:
            lr = float(lr_schedule_fn(step))
            for group in optimizer.param_groups:
                group["lr"] = lr
        else:
            lr = float(optimizer.param_groups[0]["lr"])

        # 2. 抽样取批数据
        x, y = get_batch(train_dataset, batch_size=batch_size, context_length=context_length, device=device)

        # 3. 前馈推算损失与反向传播
        optimizer.zero_grad(set_to_none=True)
        logits = model(x)
        loss = cross_entropy(logits.reshape(-1, logits.size(-1)), y.reshape(-1))
        loss.backward()

        # 4. 记录梯度状态并在剪裁约束下更新
        grad_norm = _compute_grad_l2_norm(model.parameters())
        if grad_clip_norm is not None:
            torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip_norm)
        optimizer.step()

        final_loss = float(loss.item())
        tokens_this_step = int(y.numel())
        total_tokens += tokens_this_step
        elapsed = max(time.time() - start_time, 1e-12)
        tokens_per_sec = total_tokens / elapsed

        if logger is not None:
            logger.log_step(
                step=step, prefix="train",
                metrics={"loss": final_loss, "lr": lr, "grad_norm": grad_norm, "tokens_per_sec": tokens_per_sec}
            )

        # 5. 定期执行模型测试验证循环
        if (logger is not None and val_dataset is not None and 
            eval_interval > 0 and ((step + 1) % eval_interval == 0)):
            eval_metrics = evaluate_loop(
                model=model, dataset=val_dataset, batch_size=batch_size,
                context_length=context_length, device=device, eval_steps=eval_steps,
            )
            logger.log_step(step=step, prefix="val", metrics=eval_metrics)

    total_time = time.time() - start_time
    return {
        "final_train_loss": final_loss,
        "steps": int(max_steps),
        "tokens": int(total_tokens),
        "total_time_s": float(total_time),
        "tokens_per_s": float(total_tokens / max(total_time, 1e-12)),
    }
```
